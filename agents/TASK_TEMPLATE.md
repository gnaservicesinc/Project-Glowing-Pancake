# Task assignment and handoff template

Copy the relevant section into an assignment or completion record. Replace every bracketed field with concrete task information; placeholders in this template are intentional.

## Assignment

- **Backlog ID / milestone:** [one ID; related IDs only when necessary]
- **Role brief:** [path]
- **Outcome:** [observable behavior or reviewable artifact]
- **Read first:** [specific design/specification sections and existing code]
- **Dependencies:** [acceptance evidence that must already exist]
- **Owned files/interfaces:** [bounded paths and shared contract]
- **Constraints:** [privacy, content, disk, determinism, platform or compatibility concerns relevant here]
- **Acceptance:** [small set of meaningful behaviors and failure cases]
- **Verification:** [exact available checks or required device/playtest evidence]
- **Outside scope:** [unrelated features, publication, account changes, large installations]
- **Stop/clarify only if:** [genuine missing dependency, contradictory requirement, or required authorization]

## Completion

- **Result:** [what now works or what artifact is finished]
- **Changed:** [paths and any interface/data/save changes]
- **Evidence:** [commands/checks and observed results; seed/content version/device when relevant]
- **Limits:** [what was not tested or remains uncertain]
- **Decisions:** [record IDs or no change]
- **Persistence:** [commit, successful push, final Git status; unrelated work preserved]
- **Next:** [one next unblocked backlog ID and why]

If blocked, state the exact condition and any useful work completed. A task may have partial progress without its backlog checkbox being marked complete.
